AdminAuditActivity class

app/src/main/java/com/example/se_proj/AdminAuditActivity.java
Displays security audit history, overstay alerts, zone access logs (US18), and delivery logs (US21) for administrative review.

Tab structure

  1. Audit Log — existing access_logs history with CNIC/hostId search.
  2. Overstaying — computed on-the-fly from on-campus requests past end time.
  3. Zone Logs — zone_access_logs (US18): every gate scan with zone and outcome.
  4. Delivery Logs — delivery_logs (US21): rider lifecycle and duration records.

Tabs 3 and 4 map their respective domain models to AuditLog projections so the existing AuditLogAdapter can render them without requiring new layout files.

GuardDashboardActivity class

app/src/main/java/com/example/se_proj/GuardDashboardActivity.java
Gate-operations dashboard for guards.

Extends the base check-in/check-out workflow with:

  • US18 — every scan (success or failure) is logged via ZoneAccessLogger to zone_access_logs and mirrored to access_logs.
  • US19/20 — CNIC search first checks BlacklistService; a positive result triggers a high-priority AlertManager alert and shows a popup before the visitor request lookup proceeds.
  • US21 — delivery entry and exit buttons open an input dialog and delegate to DeliveryTrackingService for lifecycle management.

WingAccessRequestActivity class

app/src/main/java/com/example/se_proj/WingAccessRequestActivity.java
Wing/lab access request screen for students and faculty.

Students request wing access for themselves; their roll number and name are auto-filled from their Firestore profile after #loadUserProfile() completes. The submit button is disabled until the profile has loaded to prevent a race condition.

A reason is required. Submitted requests appear in admin's Wing Access Management screen for approval.

WingScannerActivity class

app/src/main/java/com/example/se_proj/WingScannerActivity.java
Self-service wing access scanner (simulated kiosk).

The student enters their roll number and selects which wing they want to enter. The system checks wing_access_permissions for a valid, active, non-expired permission and shows a green "ACCESS GRANTED" or red "ACCESS DENIED" result. Every attempt — regardless of outcome — is logged to zone_access_logs.

No Firebase Authentication is required; this screen is intended to be left open on a tablet at each wing entrance.

app/src/main/java/com/example/se_proj/models/VisitorRequest.java
Domain model representing a visitor access request in the Campus Gate Access System.

Each instance maps 1-to-1 with a document in the Firestore visitor_requests collection. The class serves both pre-scheduled faculty/student requests and ad-hoc walk-in requests created by guards at the gate.

Lifecycle

A request progresses through the statuses defined in RequestStatus: pending / pending_adhoc → approved | rejected | denied | cancelled. Once approved, the guard may check the visitor in (#onCampus = true) and later check them out.

Security Model

  • #creatorId stores the Firebase Auth UID of the user who created the request and is used by Firestore security rules to enforce ownership-based access.
  • #hostId stores the human-readable roll number or faculty ID used for display and business-logic queries (e.g. guest-limit checks).

Outstanding Issues

The temporal fields (visitDate, startTime, endTime, entryTime, exitTime) are currently string-based and should migrate to structured timestamp/date types for stronger validation and query safety.

DeliveryTrackingService class

app/src/main/java/com/example/se_proj/rules/DeliveryTrackingService.java
Manages the delivery rider lifecycle (US21): entry → destination → exit → duration → overstay.

Each delivery creates one document in the delivery_logs Firestore collection. The document is created on entry (#startDelivery) and closed on exit (#endDelivery). The allowed window is #DELIVERY_WINDOW_MINUTES minutes; riders who remain on campus past that window are flagged and trigger an AlertManager delivery-overstay alert.

Edge cases handled

  • Duplicate entry: #startDelivery queries for an existing active delivery for the same CNIC and returns IllegalStateException if one is found.
  • Exit without entry: #endDelivery returns IllegalStateException when no active delivery exists for the CNIC.
  • Multiple active entries (data inconsistency): #endDelivery always closes the chronologically oldest active record first.

Firestore indexes required

  • riderCNIC ASC, status ASC — duplicate guard on startDelivery
  • status ASC, expectedExitTime ASC — overstay detection scan

VisitWindowEvaluator class

Evaluates whether a visitor can enter campus based on the approved visit window.

This class implements the Strategy pattern for gate-access decisions. Given a VisitorRequest and the current date/time, #evaluate returns a Decision that tells the Guard UI exactly what to display: status label, action button text, whether an override button is needed, and whether the attempt should be logged as a denied-access event.

Decision States

  • INSIDE — visitor is already on campus (show Check-Out).
  • AUTHORIZED — current time falls within the approved window (allow Check-In).
  • TOO_EARLY — visitor arrived before the start time.
  • EXPIRED — the visit window has already closed.
  • WRONG_DATE — the visit is scheduled for a different day.
  • INVALID_WINDOW — date/time fields could not be parsed.

For all denied states the supervisor-override button is shown, allowing a guard to manually grant entry with full audit logging.
